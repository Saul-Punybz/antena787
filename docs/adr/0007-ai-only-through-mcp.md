# AI reaches the system only through MCP, and only after it is complete

No AI runs inside Antena787. No model dependency, no API key, no cost
imposed on an organisation that has none. Instead the product exposes an
MCP server, off by default, and whoever wants an assistant connects their
own. It is the last phase built: when the phase before it is done the
product is finished, and if the MCP phase were never built Antena787 would
still be a whole system.

The reason is not principle but structure. Earlier drafts said "the AI
proposes, the human approves" — a convention, and conventions break when
someone is in a hurry. As an MCP server the rule becomes the protocol: the
surface simply exposes no tool capable of putting something to air. A model
cannot take a station off the air because the function does not exist.

Permission is decided by time rather than by operation type, on the
principle that the further from air and the more reversible, the freer the
tool. Metadata and library organisation are written directly. Schedule
changes apply directly outside a protection window — 24 hours by default —
and the same call returns a diff instead of applying inside it. The server
decides which happens, not the model. Output configuration, compliance
profiles and loudness are proposal-only regardless of timing, and a proposed
output change is proved with colour bars before it is committed.

## Consequences

Proof of play is generated deterministically by counting airing records with
emergency reconciliation applied; the model writes the prose around the
numbers and never the numbers. A model that could invent how many times a
spot aired would be producing a false business record. First delivery of a
report to any advertiser is approved by a person.

Automatic captioning (Whisper or similar) is not shipped at all — the
product carries zero AI. If a station wants generated captions, an external
tool produces the caption file and Antena787 ingests it like any other.
